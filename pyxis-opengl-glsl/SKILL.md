# Pyxis OpenGL GLSL

## 分支与寄存器

- 把只属于某条路径的取样、解码和着色放进该分支。例如，只有天空需要散射结果时，在天空分支里计算，地面分支单独重置历史。大结构体或多个 `inout` 参数穿过多层 helper 时，按实际读写拆开参数，只传用到的字段，只回写调用方会消费的结果。
- 寄存器紧张时，独立样本可以逐个读取、计算、累加，跨样本只保留累加值。两个阶段彼此独立时，先把一个阶段归约为少量值，再构造下一阶段的材质或临时结构。便宜的中间量可在下次使用时重算。若提早发出独立读取能隐藏延迟，再比较两种调度的耗时。[四点读取归约为一个标量](references/patterns.md#大量中间值跨过了分支或写入)
- 多个邻居共用视线和法线时，把重复使用的点积移出循环，随邻居变化的材质留在循环内。只枚举少数固定方向且轴索引、位移都取决于方向时，可给同一个 helper 传常量方向，比较它与动态索引循环的成本。
- 热循环反复检查 FP32 有限值时，可用指数位判定，正有限值保留浮点的 `x > 0.0`。验证取反早退、累加溢出和量化后实际使用的值。[有限值和正有限值示例](references/patterns.md#热路径反复判断浮点数是否有效)
- 若只需保留一组有限样本中的两个最大值且允许并列，可试 `min/max`。若判断可以省掉昂贵工作，保留条件分支，例如先算权重，再取有贡献的颜色样本。两者都要保留相等值、无效样本和写入的原有语义。[峰值选择、零权重与遮挡查询](references/patterns.md#选择算术还是条件读取)

## 纹理与 SSBO

- 一次读取同一 2×2 邻域的一个通道时可试 `textureGather`。每点都要 RGBA 时可试逐点 `texelFetch`。核对 mip、邻点与权重的顺序以及边界寻址。
- 当前 pass 只读且 sampler 能等价访问的图像，优先试用 `texelFetch` 替代 `imageLoad`。匹配格式、坐标和 LOD，保留前序写入对纹理读取的可见性。当前 pass 还会写的图像按原有读写和同步语义处理，读路径的收益以实际 pass 为准。[访问形状与屏障](references/patterns.md#纹理和-ssbo-的访问形状)
- 连续四个分量都会用到且布局对齐时，可以用一次 `vec4` 读写代替四次 `float` 读写，保持宿主与 shader 的偏移和步长一致。再看相邻 lane 在同一条指令中访问的地址，单条 lane 的宽读取仍可能让整个子组跨步访问。
- SSBO 定长数组过多或单个数组过长时，某些驱动会过度展开遍历循环，拖长编译时间。若缓冲布局允许，把块的最后一个数组成员声明为不定长，并保持原访问边界。声明标识符时避开 `packed`、`buffer` 和 `sample`。

## 计算工作组与实测

Ampere 的 compute pass 可从每组 128 或 256 线程试起。CC 8.6 上，每个 SM 最多驻留 16 个工作组。每组 64 线程只有两个 warp，最多占用 48 个 warp 槽位中的 32 个。CC 8.0 的对应上限是 32 个工作组和 64 个 warp。实际驻留还取决于寄存器和共享内存用量。

源码改写的预期收益先作为假设。要判断是否提速，核对输出，在同一种交付方式、相同场景、设置和工作量下比较实际运行的目标 pass。差值接近噪声时交换测量顺序或补同源码对照。需要解释差异时，再看实际访存指令、寄存器数、spill 和活跃 warp。
